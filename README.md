# Про Трансфер — лендинг-калькулятор на WordPress

Сайт трансферов (аэропорты, вокзалы, межгород по Крыму и Югу России) по механике
референса `ugtravel.ru`: **маршрут → тариф → цена → заявка**.

Стек: **Vite + Tailwind CSS 4 + Alpine.js + Яндекс.Карты**, WordPress и Carbon Fields для данных. При недоступности API используется локальный JSON. Исходный статический MVP сохранён в [mvp/README.md](mvp/README.md); текущая документация — в [docs/README.md](docs/README.md).

## Демо

Публичное превью: **https://proto0654.github.io/protransfer/** (лендинг на корне).
Дубль: `preview.html`. Рабочий WordPress-стенд: **https://protransfer.weblaba.ru/**.
Админка и расположение сохранённых доступов описаны в [инструкции стенда](docs/WORDPRESS-STAGING.md).

Деплой Pages — из ветки `main` через GitHub Actions (`.github/workflows/deploy.yml`):
пуш в `main` → сборка → публикация. Weblaba: `npm run deploy:weblaba` / workflow `deploy-weblaba.yml`.

Резервный способ (если Actions лежит) — публикация готового `dist` в ветку `gh-pages`:

```bash
npm run deploy   # build + push dist в gh-pages
```

Для него в настройках Pages нужно переключить Source на ветку `gh-pages` (папка `/`).

## Команды

```bash
npm ci
npm run dev            # http://localhost:5173 — /wp-json проксируется на staging WP
npm run build          # -> dist/
npm run preview        # локальный предпросмотр сборки
npm run deploy:weblaba # plugin/theme/MU → protransfer.weblaba.ru (SSH)
```

Стейджинг WordPress: https://protransfer.weblaba.ru/ — детали в [docs/WORDPRESS-STAGING.md](docs/WORDPRESS-STAGING.md).
На WordPress публичные данные встроены в HTML страницы. Локальная разработка получает их через `/wp-json/pt/v1/bootstrap` с прокси на стенд; таймаут, ошибка или пустые точки/тарифы включают демонстрационный JSON. Для принудительного JSON-режима задайте `VITE_DATA_SOURCE=json`. Данные редактора и загрузки хранятся на стенде, код публикуется через Git.

Статическая сборка использует относительные пути (`base: './'` в `vite.config.js`), поэтому `dist/` работает
и из корня домена, и из подпапки вида `/protransfer/` на GitHub Pages. `build:weblaba` использует базовый путь `/wp-content/themes/protransfer/landing/`.

## Как считается цена

```text
км      = Яндекс → OSRM → ручной маршрут → оценка по координатам
время   = от провайдера маршрута либо оценка по настроенной скорости
цена    = max(минималка тарифа, база + км × ставка)
        × коэффициент туда-обратно, если включено
        + стоимость выбранных опций
итог    = округление до настроенного шага
```

Настройки формулы, цены опций и округления задаются в WordPress; значения для JSON-режима находятся в `wordpress/plugins/pt-core/data/calc.json`. Подробности проверки и различия источников расстояния — в [документации WordPress](docs/WORDPRESS-STAGING.md).

«Автобус» помечен `onRequest: true` — цена в интерфейсе показывается как «По запросу».
Число пассажиров ограничивает выбор тарифа: в карточках с малым числом мест появляется метка
«мало мест», при увеличении пассажиров тариф переключается автоматически.

## Выбор точек и карта

- Поля «Откуда»/«Куда» — не `<datalist>`, а собственный список с поиском: по клику показываются
  популярные точки, при вводе — фильтр по названию, городу и алиасам (`ял` → «Ялта»).
  Работают стрелки ↑/↓, Enter, Esc и выбор мышью; клик по полю выделяет старое значение,
  чтобы можно было набрать новое.
- Карта — **Яндекс.Карты JS API 2.1** (`api-maps.yandex.ru/2.1`), блок стоит под заголовком
  калькулятора, выше полей «Откуда/Куда». Точки подписаны «А» и «Б», линия маршрута — тёмная
  с янтарным «свечением», масштаб подбирается по маршруту (`setBounds`, без `checkZoomRange`:
  с ним карта откатывается на обзорный зум и маршрут «тонет» в центре).
- Ключ API на WordPress задаётся в «Общие данные → Настройки сайта → Yandex Maps API key»; для JSON-режима — в `src/data/site.json` → `map.apiKey`. Пока ключа нет, карта рисуется,
  но в консоли браузера будет предупреждение `Invalid API key`; для продакшена нужен ключ
  (в кабинете Яндекса должны быть включены «JavaScript API», «API получения деталей маршрута»,
  при желании «Геокодер»).
- Километраж и геометрия: сначала Яндекс (`ymaps.route`) — когда задан ключ; если ключа нет или
  сервис отказал — публичный OSRM (`router.project-osrm.org`); если недоступен и он — остаётся
  собственный расчёт по координатам и прямая линия. Результаты кешируются в памяти браузера.
- Карта инициализируется лениво (IntersectionObserver), скрипт Яндекса подгружается только
  при подходе к блоку; зум колесом включается после клика по карте, чтобы не «съедать» прокрутку.


## Что происходит при отправке заявки

Приём заявок на сервер ещё не подключён. Сейчас заявка:

1. валидируется (имя, телефон, согласие, дата и время не в прошлом);
2. сохраняется в `localStorage` (ключ `protransfer_orders`, до 100 записей);
3. показывается в модальном окне с готовым текстом и кнопками «Отправить в WhatsApp»,
   «Telegram», «Скопировать», «Позвонить».

Для рабочего приёма заказов требуется серверный обработчик с валидацией и доверенным пересчётом. В `pt-core` уже есть `/wp-json/pt/v1/quote` и серверная формула, но сайт пока рассчитывает отображаемую цену на клиенте. Тип записи «Заявки» сам по себе не означает, что форма сохраняет заказы в WordPress.

Пример точки интеграции: в `src/js/app.js` метод `submitBooking()` — вместо/после `saveOrder()`
отправляйте `fetch('/api/orders', {...})` и показывайте ошибку, если запрос не прошёл.

## Что заменить перед показом заказчику

| Где редактировать на WordPress | Что проверить перед публикацией |
|---|---|
| Общие данные → Настройки сайта | Бренд, контакты, мессенджеры, тексты секций, SEO и обложка |
| Тарифы | Ставки, минималки, вместимость и фотографии автопарка |
| Тарифы → Калькулятор / Отладка | Параметры формулы и пробный расчёт без изменения сайта |
| Точки → Маршруты | Популярные пары, ручные расстояния и тариф карточек |
| Общие данные → Настройки сайта → Лендинг: Документы | Юридические тексты заказчика вместо исходных шаблонов |
| Отзывы / FAQ | Реальный контент вместо демонстрационного |
| Yandex Maps API key в общих данных | Настройки и разрешения ключа для целевого домена |

JSON в `src/data` — демонстрационный резерв, а не основной редактор WordPress. Очистка поддерживаемых полей контента и списков FAQ/отзывов не должна возвращать старые значения из демо.

В политику конфиденциальности перед публикацией нужно добавить пункт о том, что страница
подгружает карту Яндекс.Карт и прокладывает маршрут через сторонний сервис — им передаются
координаты выбранных точек. Персональные данные клиента при этом не отправляются.

## Про данные

Данные референса (`ugtravel.ru`) **не копировались**: ни точки, ни цены, ни тексты, ни фото.
Координаты точек взяты из открытых источников, ставки и минималки — собственные, тексты — написаны
для этого проекта. Формула цены повторяет рыночную механику (`max(минималка, база + км × ставка)`).
Исходные фотографии машин — демонстрационные изображения; для рабочей публикации нужны утверждённые материалы автопарка. Обложка первого экрана выбирается через медиабиблиотеку WordPress; при отсутствии выбранного изображения используется фон из текущей сборки.

## Что остаётся проверить и подключить

1. Подключить серверный приём заявок, доверенный пересчёт и согласованный канал уведомлений.
2. Пройти сохранение и повторное открытие всех полей в реальной админке; проверить пустые значения, замену изображений и мобильные состояния. HTTP-проверки и сборка эту проверку не заменяют.
3. Утвердить тарифы, отзывы, контакты, фотографии и юридические документы; выбрать режим маршрутизации для рабочей публикации.
4. При необходимости добавить фиксированные цены маршрутов, управление заказами и экспорт. Онлайн-оплата и другие расширения требуют отдельной задачи.
